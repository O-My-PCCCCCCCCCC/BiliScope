# BiliScope — 数据分析重设计（统一叙事页）设计

- 日期：2026-08-15
- 状态：设计向用户确认（用户选「统一叙事页」+ 三个新维度）
- 仓库：https://github.com/O-My-PCCCCCCCCCC/BiliScope

## 1. 背景与问题

用户对现有数据分析不满意，痛点（用户勾选）：
1. **信息太散**：分析散在 4 个页（概览/深度分析/洞察/内容分析），找不到关键结论
2. **只有数字没洞察**：全是统计数字，缺「这意味着什么」
3. **视觉/布局不好看**：图表卡片堆叠，不统一
4. **缺具体维度**：缺少「重复观看/连续活跃/深夜作息」等更有意思的维度

## 2. 目标

把分析从「图表墙」重构成「**叙事报告**」：从上到下像一个能自己讲结论的报告，AI 在顶部给出综合洞察，用户一眼看懂「我到底在 B 站看了什么、时间花在哪、兴趣怎么变、可以做什么」。

## 3. 页面结构

新增统一「**分析**」菜单项，替代现有的「深度分析」「洞察」「内容分析」三个菜单项（内容并入新页）。保留「概览」做快速入口。

新「分析」页从上到下：

### ① AI 分析报告（顶部，灵魂）
- 「生成 AI 分析报告」按钮
- 把**全部指标**（画像、时间投资、用途分布、兴趣漂移、吃灰率、连续活跃、深夜指数、重复观看、UP主深度）汇总成一段摘要，喂给 LLM
- 产出两部分：**画像叙事**（一段话）+ **关键发现清单**（每条：发现 + 数据 + 含义，如「收藏吃灰率 76.7%，188 个从没看过——建议清理」）
- 无 LLM 配置时提示去设置
- 生成结果不落库（每次点生成）

### ② 精选核心指标（3-4 个，带一句解读）
- 总观看时长（小时）/ 活跃天数 / 黄金时段 / 最沉迷UP主
- 每个卡片下加一句自动生成的解读（如「活跃 57 天，日均 21 条，集中在 22 时」）

### ③ 主题化分区（每块 = 一句话洞察 + 图表）

| 分区 | 内容 | 一句话洞察 |
|---|---|---|
| 时间花在哪 | 时间投资榜（用途/主题/UP主）+ 用途占比 | 「你的时间大头在 X」 |
| 兴趣怎么变 | 兴趣漂移堆叠面积图 | 「兴趣从 X 迁移到 Y」 |
| 什么时候看 | 时段×内容热力图 | 「深夜是 X 的重度时段」 |
| 收藏行为 | 吃灰率 + 吃灰明细 | 「X% 收藏从没看过」 |

### ④ 新维度（3 个）

| 维度 | 内容 | 数据 |
|---|---|---|
| 重复观看 / 沉迷视频 TOP | 同一视频看几遍（按 bvid 计数）+ 单视频累计时长 TOP | `history` 现成 |
| 观看连续 / 活跃周期 | 最长连续观看天数 + 近 90 天活跃日历 + 周活跃趋势 | `history` 现成 |
| 深夜指数 / 作息健康度 | 凌晨(0-6)观看占比 + 工作日/周末节奏 + 「熬夜指数」标签（如偶尔/经常/重度夜猫） | `history` 现成 |

## 4. 后端设计（模块化）

- `app/insights/watching.py`（新）：三个新维度聚合，独立模块+独立测试
  - `repeat_watches(conn, limit=10)` → `[{bvid, title, up_name, views, total_sec}]`
  - `streak_stats(conn, days=90)` → `{longest_streak, active_days, weekly: [{w, n}], calendar: [{day, n}]}`
  - `night_owl_stats(conn)` → `{night_ratio, weekday_ratio, night_level}`
- `app/insights/ai_report.py`（新）：AI 综合分析报告
  - `generate_ai_report(conn, llm_client)` → `{narrative, findings: [{title, detail}]}`
  - 汇总全部聚合函数 → 摘要 → LLM 产出叙事 + 发现清单（prompt 要求结构化）
- `app/analyze.py` 已有的 `watch_profile` / `category_distribution` / `aggregate_themes` 等复用

## 5. API

- `GET /api/analysis/overview-report` → 页面的全部数据一次拉齐（核心指标 + 各分区数据 + 三个新维度），减少前端 N 次请求
- `POST /api/analysis/ai-report` → 生成 AI 分析报告（需配置 LLM，未配置 400）

## 6. 前端设计

- 新组件 `AnalysisPage`（重写现有 Analysis 组件），按 ①②③④ 结构布局
- 菜单：`分析` 替换 `深度分析`+`洞察`+`内容分析`（三个旧菜单项移除，组件保留但不再挂菜单，避免一次性删代码风险）
- 图表风格统一：沿用 ECharts dark + 统一配色；卡片用统一间距；每分区头部放一句话洞察
- 概览页保留不变（快速入口）
- 「重新分析全部」按钮挪到分析页底部（管理区）

## 7. 测试

- `tests/test_watching.py`：重复观看计数、连续天数（含跨天边界）、深夜占比
- `tests/test_ai_report.py`：mock LLM 验证汇总摘要包含关键指标、返回结构 `{narrative, findings}`
- API 测试：overview-report 返回结构、ai-report 未配置 400
- 全部离线 mock，不请求真实 LLM

## 8. 非目标（本轮不做）

- 不做基准对比（与全站平均对比，需外部数据）
- 不做僵尸关注/断更UP主（用户本轮未选）
- 不做流式输出（分析报告一次性返回即可）
- 不删旧组件文件（只撤菜单挂载，降低风险）
